# Passive allocation-recipient facts

Owner: Hari Krishna Kancharla.

This component records which actual local Request received concrete allocation returns in the pinned ordinary vLLM path. It is the first part of a read-rights join. It does not establish attention permission, a still-live exclusive grant, transfer admission, lease validity, content provenance, tenant authorization or physical device loads. Those outputs remain unknown. The saved #61229 events do not contain this new evidence and remain unknown under this contract.

The mode is off by default. An internal caller must explicitly pass `recipient_factory=AllocationRecipientObserver` to the existing `mapping_factory` or `MappingObserver`. No environment switch, serving command or current owner packet enables it. The existing assignment schema is unchanged. The broader operator/common-evidence workflow does not yet ingest these captures, and the full feature is unfinished.

The source profile is exact vLLM 0.32 at 5df63a7203cdb9328d824a27b682e77c7b9928be. It retains the existing 36 source pins, Qwen3 dense full-attention model profile, immutable observed model revision, single pool/group, prefix caching off, eager V2 and UniProc topology. It additionally requires the actual synchronous Scheduler, async_scheduling=False, no custom scheduler, no deferred block free, ordinary n=1 Request and no sharing, unpin, CoW, offload, replay, preemption or unresolved frame/call overlap. Missing or unsupported facts are unknown. Synchronous scheduling can still initiate an async KV load; destination capacity allocation is not successful load admission.

The observer binds the actual Request object at outer allocate_slots entry to the already observed initialization graph. It records native coordinator/lower phases and the actual successful pool returns with the existing acquisition mutation identity and ordinal. Ordinals are observation labels, not native lease nonces or byte generations. Grants are never reconstructed from a later req_to_blocks row, reference counts, request names or timestamps. Empty returns, outerNone, normal completion and exceptional closure remain distinct. A missing grant never means unowned.

Original bodies run once with their original arguments. Results retain object identity. Native exception instances and their native traceback tails are preserved; wrapper frames can appear. Recorder failures make evidence unknown. No lock spans a native body and no additional device copy is installed. A known lifetime wrapper can compose only through exact registered delegation, with both observers checking actual slots and callable/code identities. Arbitrary markers or unwrap chains are unsupported.

Attachment freezes every observed mapping hook chain, including the bare outer and coordinator wrappers, lower and pool mutation wrappers, scheduler wrapper and direct helper/getter paths. Coverage rechecks exact defining slots, installed and supplied code objects, every closed delegation cell, native leaf identities, dynamic recipient routing and the captured inventories. It validates only the actual reviewed templates and registered outer lifetime composition. Once a code, slot or delegation loss is observed, restoring it cannot make that interval healthy again.

Before attachment can become covered, all 22 native originals are compared with their complete defining functions in the existing pinned source files. This includes dormant guards, the Scheduler and the direct getter. Normal inheritance is resolved to the defining class. The only supported native outer closure is the source-proved `__class__` cell bound to that exact class. Unsupported initial code refuses setup and owned hooks are cleaned up without changing that original. Detached wrapper-helper controls cannot establish a supported engine profile.

Collection is bounded host metadata in memory. It is not a durable live recorder: a crash before explicit export leaves no recipient capture. The separate limits are 1024 outer calls, 4096 phase calls, 512 blocks per return, 8192 total block facts, 16384 records, 256 KiB per record, 16 MiB per recipient journal and 262144 aggregate JSON nodes. Rejected record admission is counted and makes the result unknown. These caps do not qualify the current owner recipe, live overhead or another model/configuration.

After the mapping interval closes, retain its actual journal and separate settled-close receipt with `mapping_closure.capture_closed`. Pass their exact byte dictionaries to `allocation_recipient_recording.write_capture(observer.recipient, new_directory, payload, receipts)`. This creates a new local packet with the recipient journal, paired mapping bytes and a manifest written last. Existing output directories are refused. Missing or unhealthy settlement retains an explicitly incomplete recipient file and an unknown result. No healthy footer substitutes for the settled receipt. Actual process shutdown remains separate.

The observer admits one export attempt under its bookkeeping lock. A failed attempt consumes that attempt, including an existing destination or interrupted write. Partial outputs are retained. A second caller or destination is refused; no automatic retry is performed. The lock never spans an original native body.

`allocation_recipient_recording.verify(directory)` checks exact local inventory/hashes, calls mapping_closure.validate_captured on the actual byte pairs, replays the mapping initialization/acquisition semantics and replays the new recipient call chain. It works after copying the packet, without the original recording directory, engine, network or device. Hashes establish local consistency, not authenticity or remote attestation. A consistent packet with missing facts remains unknown. A complete positive receipt is reported as observed capacity attribution; scope_verdict stays inconclusive and no whole-deployment safety result is produced.

The external packet inventory consumes names one at a time through directory descriptors and visits only the declared root and optional mapping directory. Unknown names, links and nonregular files refuse before content reads or descent. Only the strict listed files are read, with a remaining aggregate byte allowance. Exact file and directory names are compared again before and after the final byte recheck.

Fresh implementation review, final unchanged CPU suites, operator collection/export integration, revised source-derived live budgets and owner validation remain required before the full read-rights feature can be called complete.
