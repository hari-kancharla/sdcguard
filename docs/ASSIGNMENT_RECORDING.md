# Bounded assignment journal

Owner: Hari Krishna Kancharla.

`sdcguard.lifetime.assignment_recording.AssignmentRecorder` stores one finite assignment observation interval. It has no engine/device import, activation, native call or model hook. It does not establish source authenticity, allocator associations, complete read rights or physical reads. The offline assignment evaluator remains the authority for semantic verdicts.

Construct it with a recording directory and the actual supported adapter, source SHA map, effective profile, complete coverage names, dependency observations and a process-incarnation UUID. The header is validated against the installed assignment contract and copied into ordinary bounded JSON before creating a directory or file. Caller mutation cannot change stored bytes. Optional shared health supplies `snapshot()` with a boolean `healthy` and nonnegative integer `errors`.

`emit(kind, **facts)` takes the kind positionally and admits an immutable serialized copy to a bounded asynchronous writer. It returns false on unsupported JSON, reserved envelope fields, unsupported event names, exhausted budgets, a full queue, lost writer health or closure. Header/footer markers are journal-owned. The queue holds at most 1024 waiting records plus one in-flight record. Its 8 MiB byte limit includes both waiting and in-flight records. Records, bytes, nodes and nesting use the assignment contract limits, with space reserved for the footer. It does not expand records by token count or invoke caller conversion methods.

The integrated collector raised the waiting-record limit from 32 to 1024 after an ordinary 16-request CPU burst lost 54 records at the old limit. The byte, semantic record, frame, node and cell bounds are unchanged. This provides room for the tested burst and its nested mutation facts. It is not a completeness guarantee under arbitrary scheduling or storage delays. Saturation still records drops and produces unknown; required transitions are never sampled.

`gap(reason)` marks sticky error accounting and attempts a gap record. Missing facts must never be replaced with a plausible event. Disk, short-write, queue, budget and health failures remain unknown through the unhealthy footer or an unfinished file. No native operation is retried.

The writer creates `<session>.jsonl.incomplete` exclusively with mode 600, using the accepted no-follow anchored directory handling. The final `<session>.jsonl` appears only after the footer flush and file close succeed. Publication uses an exclusive hard link in the same anchored directory and never overwrites an existing destination. Successful publication removes the temporary link. A failed recording invalidates its footer before attempting to restore the incomplete name. A retained writable descriptor identifies the owned inode even if either name changes. Recovery also checks both names without following symlinks and never truncates or removes a name observed to belong to another inode. A failed rollback link or cleanup can leave the final name, but its bytes remain incomplete when footer recovery succeeds. All accepted body records are retained.

Footer invalidation and naming cleanup remain best effort if every available descriptor and verified path rejects further recovery. This component cannot promise durable rollback after total filesystem failure or external deletion of all owned names. An unhealthy or timed-out close must never be accepted from filenames or parseable bytes alone. Callers must retain the close result and status. A successfully sealed historical interval is not reopened or rewritten by later calls.

`close(timeout=1.0)` stops admission and waits for the requested writer-join budget, capped at five seconds. It never acquires the record/state lock or performs filesystem work. A separate short terminal arbitration contains no serialization, health callback, state-lock wait or filesystem operation. The bound is a thread wait budget, not a hard real-time guarantee against process scheduling delays. A timeout returns false and marks the interval unhealthy while the writer may still be blocked in storage. Recovery runs when storage work resumes, including when the data file has not closed or publication has not begun. Until recovery settles, raw bytes can still contain a healthy footer. A blocked publication cleanup may also leave a final filename temporarily. An offline parser can evaluate such prematurely captured bytes as satisfied because it does not observe the live close result. Neither those bytes nor a filename override the false close result. Packet intake rejects a directory containing `.jsonl.incomplete`; callers must also require a successful close and settled status before exporting any final file. `status.closed` reports whether writer finalization has settled. A later close call can wait another bounded join budget for cleanup, but a timed-out interval never becomes healthy again. True means writer finalization and publication succeeded with no dropped/error/shared-health evidence. It does not mean the recorded rule is satisfied. A false result must not be accepted. A failed or timed-out finalization is an incomplete recording, even if a cleanup failure leaves a final filename. A completed file with an unhealthy footer also returns false and remains unknown. Header and footer both count toward `records`; `samples` counts written `frame_end` events, and `acquisitions` counts written `acquire` events, including a valid acquisition of zero blocks.

`session`, `process`, `path` and `incomplete_path` are readonly properties. `status` returns an independent snapshot. A changed PID returns unavailable status before touching inherited locks, queues, threads or shared health. A caller must not reuse an inherited recorder after a fork.

The assembler must retire and quiesce producers and shared-health callbacks before closing, account for every positive dispatch, and mark open mutations or frames unhealthy. It must check `close()` and `status` before accepting a packet. Rejections during the open/closing interval affect its health. Later callback attempts are outside the successfully sealed historical file; they return false and increment a separate late-call observation without reopening or rewriting that file. They must not be presented as covered observations.

This is an inactive storage component. The complete native assembler, independent component review, combined CPU suites, package checks and owner-run validation remain separate gates.
