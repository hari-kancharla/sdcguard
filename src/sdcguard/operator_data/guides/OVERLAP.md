# Overlap with existing work

Read October 27, 2026. Source-based comparison, not a head-to-head measurement. Paper results belong to their authors. No novelty or superiority claim is established.

| Primary source read | Mechanism and overlap | Distinction and limit |
| --- | --- | --- |
| [GRIEF v1](https://arxiv.org/html/2605.11202v1), sections 2–4 and appendix A.2–A.7 | Mutates timed concurrent vLLM/SGLang request traces; combines behavioral checks, log-probability replay and adapter-specific KV lifecycle forensics. Direct overlap with serving correctness testing and replay. | The paper reports developer-confirmed vulnerabilities. This package preserves one already-public known case. Structural evidence and replay are not novel by themselves. The anonymized artifact was opened but yielded no readable source in the web reader; implementation was not independently validated. |
| [Antithesis architecture](https://antithesis.com/docs/introduction/how_antithesis_works/) and [debugging](https://antithesis.com/docs/product/debugging/) | Explores executions against properties in a deterministic environment, with replay and causality analysis. Overlaps with explaining execution-dependent failures. | Reviewed documentation does not establish equivalence to this particular real-GPU NIXL case. Neither a GPU capability gap nor a performance advantage is claimed. This scope adds no exploration. |
| [Vosti v1](https://arxiv.org/html/2609.38981v1), sections 2–5 and 7 | Verifies scheduling and prefix-sharing caches against deterministic-logit requirements using Verus and kernel contracts. Adjacent determinism prior art; a readable primary source was reverified on October 27. | Its proof applies to its engine under assumptions. Section 7 separates determinism from functional correctness. This package checks observations of an existing engine; it does not inherit that proof. |
| [OpGuard paper](https://www.usenix.org/system/files/osdi26-zhou-ziming.pdf), sections 3–4, 6 and appendix A; [README](https://github.com/OrderLab/OpGuard) | Adjacent numerical-integrity/training diagnosis: aligns operator fingerprints, identifies the first computational difference and provides debugging context. The public harness supports coding-agent investigation. | Evidence-based diagnosis and agent integration already exist. The paper also includes online SDC detection, not just offline diagnosis. This package has not demonstrated better localization. |
| [AEGIS paper](https://www.usenix.org/system/files/osdi26-lei.pdf), sections 3–8 | Adjacent training-time integrity: separates lightweight sensing from verification, using recomputation and checksums. Prior art for online detection and preserving replay context. | Production evidence is not this project's evidence. Confirmed checksum localization used FP32 accumulators; rounded BF16 checksums did not locate those incidents. This serving software case is not evidence of finding a faulty GPU. |
| [AI21 investigation](https://www.ai21.com/blog/vllm-debugging-mamba-bug/), reproduction, request identity, root cause and fix sections | Traces rare output corruption to scheduling/state handling and carries request identity into model execution. Prior art for request-aware inference debugging. | An engineering investigation, not evidence of a general checker. It shows why correct kernel math is insufficient. Reproducing another known issue does not establish novelty. |
| [TensorRT-LLM lifecycle arbitration](https://github.com/NVIDIA/TensorRT-LLM/blob/0a03c3ed057fe8c488e221413640ca87f64e99d2/tensorrt_llm/_torch/disaggregation/lifecycle/README.md) and [Dynamo KVBM architecture](https://github.com/ai-dynamo/dynamo/blob/45e30e07a4f4cef37ab7bfa739f7bee0c89b3057/lib/kvbm-engine/docs/architecture.md) | Vendor prior art includes shared retirement/deadline arbitration, physical-operation ownership and distributed/tiered cache coordination. The lifecycle documentation explicitly separates logical outcomes from physical access-end evidence and requires resource-root binding. | The claim that vendors will never own shared lifecycle work is unsupported. These documents do not establish an equivalent independent operator acceptance product, nor an absent capability. They are third-engine research inputs, not supported adapters in this package. |
| [ResidentClaim lowering](https://arxiv.org/html/2606.01387v1), obligations, runtime studies, checker and limits | Checks anchored evidence against shared obligations across TensorRT-LLM, SGLang/HiCache, Dynamo and patched vLLM. Explicitly distinguishes missing facts and adapter evidence from native conformance. | Close overlap in cross-engine rule vocabulary, evidence boundaries and conservative classification. Its accepted future-reuse/restoration obligation differs from this package's source lease and destination-retirement contracts. Shared rules and portable evidence alone are not a novelty claim. |
| [vLLM RFC #53194](https://github.com/vllm-project/vllm/issues/53194), [tier conformance proposal](https://github.com/vllm-project/vllm/pull/53769) and [entrypoint proposal](https://github.com/vllm-project/vllm/pull/55886) | Key-partition conformance, paired positive controls and an executable registry-based coverage gate with explicit exemptions. | Different property from asynchronous transfer retirement. Both PRs were open and unmerged on this read. Proposed upstream coverage is not shipped coverage, but cache conformance and release gating already have substantial upstream work. |
| [kvcache-sanity-check](https://github.com/yanok/kvcache-sanity-check/blob/40a8313079cbc2a44b6473c36bb5cdd64441de23/README.md) | Installed reference/target answer regression command, logs and CI exits, with LMCache segmented prefill as its main target. | The inspected path compares answers through a running endpoint. This package's resource/event obligations use different evidence. That relative difference does not establish an absent competing product. |
| [Metria upgrade implementation](https://github.com/dipeshbabu/metria/blob/3ca1e88846a90d7a9c61e3175986b66025b2b773/src/metria/verification_upgrade.py) | Exact runtime-version transition, separate pinned environments, same model/workload, requested/resolved/observed identity and explicit permitted deltas without waivers. | Direct overlap in upgrade workflow and identity discipline. Its inspected acceptance criterion uses token trajectories and behavioral analysis. This package judges named KV transfer/config contracts. An independent upgrade gate by itself is not distinctive. The competing implementation was read, not executed here. |
| [KVSentry SGLang rules](https://github.com/angelnicolasc/KVSentry/blob/6793f1c96f12fa030641a2c8b04115e8c4db6ac9/core/rules/sglang.yaml) and [repository](https://github.com/angelnicolasc/KVSentry) | Cross-engine static rule packs for vLLM/SGLang, cited mitigations, unknown-version coverage gaps and CI/admission reporting. The inspected properties concern cache keys, hashing and timing isolation. | Direct overlap in independent cross-engine static auditing. Different properties from transfer retirement and the pool/context contract. Static rules, unknowns and a CI exit code alone are not the distinction. The project was not executed here. |

Also read: [Cloudflare's October 26 report](https://blog.cloudflare.com/kv-cache-exposure-remediation/) and [SGLang's update](https://www.lmsys.org/blog/2026-10-26-cf-security). Transfer checksums and KV canaries already exist upstream. Cloudflare describes a page-generation prototype disabled for reliability issues and ongoing protocol verification. Proposals and completed coverage remain distinct.

The bounded work here is conservative bookkeeping, separate terminal outcomes, exact source matching and portable reporting around the saved #61229 case, plus declared static contracts and ordinary CPU component observations. Those mechanisms have substantial prior art. Comparative performance and deployed generality remain unmeasured.

Current upstream status: [vLLM issue #61229](https://github.com/vllm-project/vllm/issues/61229) and [proposed PR #62065](https://github.com/vllm-project/vllm/pull/62065) are open/unmerged as checked October 27. The local backport is not a released official fix. The remaining product hypothesis is maintained, source-reviewed KV transfer and configuration contracts for a declared stack across actual version changes. That property and its exact mappings need to be demonstrated. This table does not establish a general or uncontested product moat.
